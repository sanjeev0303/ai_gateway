    │
    ▼

## Credential Concepts (Distinct, Not Duplicate)

The repository uses two gateway authentication mechanisms that look similar but are intentionally separate:

| Name | Route | Purpose | Status |
|---|---|---|---|
| API Credentials | `/v1/credentials` | Legacy gateway API keys | Done |
| Gateway Credentials | `/v1/gateway-credentials` | Scoped keys with subject, team, project, expires | Done |

**Decision**: Keep both. API Credentials map to the old simple-key model; Gateway Credentials are the newer scoped model with full lifecycle management. The UI labels them clearly in the section registry. No consolidation needed — both types exist in the domain with different semantics.

## Critical Bugs Fixed in Prompt 01

### Policy Enforcement String Mismatch (FIXED)
- **File**: `internal/interfaces/gatewayv2/policy_resolver.go`
- **Bug**: `buildSnapshot` filtered `policy.Enforcement != "enforced"` but DB CHECK only allows `('permissive', 'active', 'disabled')`. The value `"enforced"` never matches, so **no policies were ever loaded**.
- **Fix**: Changed to `policy.Enforcement != "active"` (using `domain.EnforcementActive`)
- **Tests**: Updated `policy_resolver_test.go` to use `domain.EnforcementActive` in all stubs. All tests green.
